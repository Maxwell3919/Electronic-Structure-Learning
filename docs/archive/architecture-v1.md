# Architecture

## 1. Static-first structure

```text
Machine-readable source maps and site registries
        │
        ├── Martin: 7 Parts / 46 units
        ├── Sholl–Steckel: 10 practice units
        ├── navigation, paths, status, labs, cases, reference
        ├── 46-unit source-semantic audit and terminology registry
        └── empty-first literature, claim, queue, and discussion contracts
                    │
                    ▼
          MDX route skeletons
                    │
        ├── directory-level page locators
        ├── reusable outline components
        ├── future original explanations
        └── interactive teaching components
                    │
                    ▼
       deterministic Node validation
                    │
                    ▼
             Astro static build
                    │
                    ▼
         GitHub Pages public deployment
```

The site remains static-first. MDX stores learning pages; small client-side components are used only where interaction has a clear teaching purpose.

## 2. Content layers

The previous architecture organized content around Martin and Sholl–Steckel source structures, route skeletons, registries, literature layers, labs and cases.

## 3. Authority boundary

The previous architecture defined repository, deployment, source material, private records, raw calculation data and derived data boundaries.

## 4. Components

The previous architecture defined reading, navigation, source, derivation, visualization, theory and literature components.

## 5. Validation

The previous architecture defined deterministic structural, runtime, literature, terminology and build validation.

## 6. Scientific data flow

External calculation results were intended to be processed into read-only website visualizations. The browser was not intended to run production DFT calculations.

## 7. Deferred capabilities

Accounts, databases, backend services, Slurm submission, large object storage and online production calculations were deferred.
